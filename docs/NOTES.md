**Restreamer split pipeline** (optional): ATEM streams to a Restreamer (datarhei Core) instead of direct-to-Overseer; Restreamer fans out to an auto monitor-copy back into Overseer's node-media-server ingest (tile preview unchanged) + N egress destinations (YouTube/Twitch) managed per-device in the gear panel. Built as a **portable workspace package `@av/restreamer`** (`packages/restreamer`, zero app coupling — datarhei Core v3 client w/ JWT login+refresh, `SplitManager` building the split process [monitor=output0, enabled dests after, all `-c copy`], in-memory mock transport) so **flock** drops it in (pass its own monitorUrl + `referencePrefix`). Server: `restreamerService.ts` (monitor URL = Overseer ingest, dest persistence in config.restreamer.channels, mock in --mock, docker-compose generator), REST under `/api/restreamer` + `/api/devices/:id/restreamer/*`, and `streamingXml.ts ingestTarget()` points ATEM at Restreamer when enabled. Config: `restreamer` block {enabled,url,username,password,rtmpHost/Port/App/Token,referencePrefix,channels}. Enabled in mockConfig. Verified vs mock transport only (NO live Restreamer — no Docker here); generated process JSON matches documented v3 schema. NOTE: `launcher/scripts/prepare.sh` vendors `@av/*` workspace pkgs into the embedded node_modules (not on npm) — verified assembled app boots. NOTE: root `typecheck` must `build:libs` first (server typecheck needs @av/restreamer dist d.ts). docs/restreamer.md + packages/restreamer/README.md (flock porting guide).

**Device management** (top-bar "Devices" panel): best-effort mDNS/DNS-SD discovery (`server/src/discovery.ts`, enumerates advertised service types, keeps blackmagic/atem/nmos matches; mock-seeded), runtime add-by-IP/hostname + remove (persisted to config, WS 'fleet' re-sync), per-device info (model, IP, reverse-DNS hostname, record filename, protocol version — NOTE: ATEM protocol exposes NO firmware string, only apiVersion), and launch buttons for ATEM Software Control/Setup/MixEffect/Fleet Manager (`server/src/externalApps.ts`, spawns local app; BMD apps have no public deep-link so they launch+copy IP to clipboard, MixEffect uses URL scheme; all overridable per-platform via config.externalApps with {ip}/{host}/{name}). Verified vs --mock in-browser.

**Stack:** npm-workspaces monorepo (like [rfutils](https://github.com/stoatworks-labs/RFutils/blob/main/docs/NOTES.md) (`RFutils`)).
- `packages/server` (Node/TS): `atem-connection` device manager + normalizer (`atem/normalize.ts`), `atem/mock.ts` synthetic fleet for `--mock` (hardware-free dev), `node-media-server` v2 RTMP→http-flv ingest (stream key = device id), Streaming.xml + Overseer config XML gen, Express REST + `ws` WebSocket bridge. Entry `src/index.ts`, `--mock` flag.
- `packages/web` (Vite/React/TS): multiview tiles, canvas Fairlight audio meters (read levels via ref @ display rate), `mpegts.js` live preview, per-device browser-side monitor mute, remote transport, gear panel (media-pool upload via browser RGBA conversion, media-player assign, streaming/config XML).

**Run:** `npm install`, then `npm run dev:mock` (dashboard :4700). Real: copy `atem-overseer.config.example.json` → `atem-overseer.config.json`, `npm run build`, `npm start`. Ports: 4700 dashboard, 1935 RTMP, 8000 http-flv. `publicHost` baked into Streaming.xml + flv URLs.

**Live-hardware validated 2026-07-17** (read-only) against a real **ATEM Mini Extreme ISO at 192.168.1.14** (BMD OUI 7c:2e:0d, mDNS hostname ATEM-AVE-7c2e0d16505d.local, on 192.168.1.x LAN, our host 192.168.1.90). Confirmed working: `atem-connection` transport (control port UDP 9910), full state normalization via `/api/snapshot` (connection=connected, model, record/stream status=idle, record filename, audio levels, media-player slot names), and **mDNS discovery via `/api/discovery`** (found the device as `_blackmagic._tcp`, correctly `alreadyManaged:true`). NOTE: on this real device the normalized `protocolVersion` field returned **"8.1.1"** (raw atem-connection `state.info.apiVersion` int was 131102 = 2.30 — the normalizer's protocolVersion is NOT that packed int; revisit line-12 "no firmware string" claim). Real-device config lives in `atem-overseer.config.json` (gitignored).

**Full streaming ingest + record actuation validated 2026-07-17** (user attached a record drive + connected a source, then approved actuation). RTMP ingest end-to-end WORKS on real hardware: `POST /api/devices/mini-extreme/streaming-service` (the "Apply local service to switcher" path) repointed the ATEM to `rtmp://192.168.1.90:1935/live` key=`mini-extreme`, `POST .../stream {action:start}` → node-media-server ingested the publish (`stream.live:true`, bitrate ~162kbps), and http-flv re-serve returned a valid `FLV`-header stream (94KB in ~1s). Record start/stop also works (disk "Allan", free frames dropped, proving real write). **Record/stream duration-timer bug — FIXED 2026-07-17.** Root cause: the ATEM only reports record/stream `duration` when asked (`requestRecordingDuration()`/`requestStreamingDuration()`), it doesn't push a per-second tick — so overseer's tile timers sat frozen at 00:00:00 for the whole capture. Fix in `packages/server/src/atem/realDevice.ts`: a 1s `setInterval` (started on 'connected', cleared on 'disconnected'/stop, `.unref()`'d) that calls the request methods ONLY while `state.recording.status.state===Recording` / `state.streaming.status.state===Streaming` (idle otherwise = no added traffic); each reply updates state.duration and fires 'stateChanged'→pushSnapshot. Verified live on the real Mini Extreme ISO: record timer ticked 00:00:00→05, stream timer ticked 00:00:00→06. NOTE: atem-overseer has NO test framework configured (no vitest, unlike animATEM/fleet-admin), so this was verified by live hardware only, not a unit test. IMPORTANT restore discipline: the device's original streaming service (Restream.IO, url rtmp://live.restream.io/live, key "" empty, bitrates [6M,9M]) was saved before and restored+verified after — always save/restore streaming service around this test since the overseer endpoint only sets its own service. Still UNtested on real hardware: media/still upload.

**Scope notes:** metering always shown (mute = local playback only); "drive capacity" = ATEM's recordingTimeAvailable (protocol gives no raw bytes), bar uses 4h nominal-full; config XML = Overseer fleet/ingest config, not full ATEM state backup, device changes need restart.

Key ATEM API facts (atem-connection 3.9): events connected/disconnected/stateChanged/levelChanged; `startFairlightMixerSendLevels()` to enable meters (master levels leftLevel/rightLevel/leftPeak/rightPeak dB); commands startRecording/stopRecording, startStreaming/stopStreaming, setEnableISORecording, setStreamingService, setRecordingSettings, setMediaPlayerSource, uploadStill; ISO vs PGM = recording.properties.recordInAllCameras.
